把 70–117 MB 一尊的三维资产，
压到能在手机里真实旋转。

《江格尔》史诗非遗数字化采集产出的原始三维资产，单尊 150 万三角面、 单模型 70–117 MB。而它真正需要触达的阵地是手机浏览器与微信—— 弱网、低端设备、以及微信小程序 1.5 MB 的主包上限。

本系统是解决这一矛盾的构建期处理管线 + 运行时跨端渲染引擎： 配置驱动，{外部库 0 个，Draco 解码器 0 个，CDN 依赖 0 个}。

这一页的所有数字都是构建期从 GLB 二进制里量出来的，不是手写的。 运行 node scripts/assetctl.mjs all 可完整复现本页全部指标—— 这是本作品"可验证性"的实现方式。

软件架构

四层分离：构建期管线只读解析容器、产出双级资产与清单；运行时引擎只负责解压与绘制； 应用层承载展馆、图谱与 AI 叙述；数据层用单一数据源保证双端一致。 层与层之间以**文件契约**（manifest / 数据集 JSON）耦合，因此管线可脱离本项目复用。

CONTRACT

级间契约

管线不直接调用渲染代码，只产出文件：双级 GLB + manifest.json。 渲染引擎不关心资产怎么来的，只读清单。

  • 替换资产来源：改 assetctl.config.json
  • 替换渲染目标：实现同一清单读取契约
  • 契约变更可被预算断言与校验脚本拦截

顶点缓存效率（ACMR）

ACMR（Average Cache Miss Ratio）是 GPU 后变换缓存命中率的行业指标，1.0 为理想值。 本项检查用于回答一个具体工程问题：轻量版能退回 16 位索引吗？ 16 位索引可再省一半索引字节，但顶点复用率不足时反而拖慢绘制。 实测 u16 预检值整体升高至 1.365，因此轻量版保留 u16（体积优先，因该级受 750 KiB 硬约束）， 精细版保留 u32（绘制效率优先）。

命令行接口

一条命令复现本页全部数字。管线是独立的命令行工具，不依赖本项目其余代码。

# 全量：解析资产 → 校验预算 → 顶点缓存分析 → 写出 JSON/Markdown 报告
node scripts/assetctl.mjs all

# 单独跑某一项
node scripts/assetctl.mjs verify      # 仅校验预算与完整性（CI 门禁用，失败退出码 1）
node scripts/assetctl.mjs report      # 仅生成逐资产量化报告
node scripts/assetctl.mjs cache       # 仅做顶点缓存效率分析

# 限定级别 / 指定输出目录
node scripts/assetctl.mjs report --tier=preview --out=reports/preview

# 产物
#   reports/asset-report.json   机器可读，供 CI 与页面消费
#   reports/asset-report.md     人可读，可直接附入参赛材料
#   public/console.html          本页（由 gen-console.mjs 读报告生成）

DESIGN CHOICE

为什么自己解析 GLB 而不用现成库

不是重复造轮子，是约束条件决定的。

  • 微信小程序主包上限 1.5 MB，不允许下载外部解码器
  • 网页端要求零第三方脚本，避免外部依赖成为唯一故障点
  • 自研换来的是：完全可控的加载策略、体积预算与失败降级路径

DESIGN CHOICE

为什么不用 Draco 而用量化

Draco 压缩率更高，但需要附带第三方解码器代码（体积与许可双重成本）。

  • 改用 glTF 官方扩展 KHR_mesh_quantization
  • 顶点属性紧凑存储：位置 6 B / 法线 3 B / UV 4 B，合计 13 B/顶点
  • 解压由自研运行时完成，零第三方代码

REUSABILITY

换一批资产怎么用

管线与"江格尔"这一具体内容解耦，只依赖配置文件。

  • 改 assetctl.config.json 的 tiers 与预算
  • 指向新的资产目录，重新运行 assetctl all
  • 预算断言与报告自动适配新资产
