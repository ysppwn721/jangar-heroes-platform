# 十二英雄模型重制 · 交付要求

> 给做模型的同学：**按这份要求导出，就能一键接进现有网站**；不满足的话管线会在体检阶段就拦下来
> （不会做出一半才失败）。体检命令：`node scripts/ingest-models.mjs --check`

---

## 一、为什么必须先看这份

现存十二尊是 **AI 图生 3D**（混元等），问题不在"不够精细"，而在**细节本身不存在**——
所以任何"标注细节"的设计都站不住。重制的目标不是更好看，而是**真的有细节可讲**。
（史料侧的结论见 `tools/research/十二英雄形象研究.md`：史诗不写长相，写的是职分、坐骑、兵器与九十九种美德，
所以**风格化/卡通形象比写实更贴近史诗本性**，也不容易变成"伪造史料"。）

技术侧我们已核对过：现有管线的能力足够承载新模型，**唯一需要你配合的是导出格式**。

---

## 二、五条硬要求（不满足 → 体检直接拒绝）

| # | 要求 | 为什么 | 不满足的后果 |
|---|---|---|---|
| 1 | **单个 mesh、单个 primitive** | 管线只读 `meshes[0].primitives[0]` | 只渲染出其中一个部件 |
| 2 | 属性齐全：`POSITION` / `NORMAL` / `TEXCOORD_0` / `indices` | 渲染器需要法线做光照、UV 做贴图；缺索引无法按三角形处理 | 导入报错 |
| 3 | 节点旋转必须是**精确的 +90° X 四元数** `[0.7071068, 0, 0, 0.7071068]` | 管线靠它把 Z-up 转成 Y-up，并烘焙进几何 | 抛 `Unexpected source transform`，**这一步最容易踩** |
| 4 | 三张贴图齐全且**内嵌在 GLB 里**：基础色 / 法线 / 金属粗糙 | 管线直接从 GLB 的 bufferView 读图；法线贴图决定"看起来像不像实物"，是观感损失最大的一环 | 导入报错或画质显著变差 |
| 5 | 贴图格式 **PNG 或 JPEG**（不要 WebP/KTX2/BasisU） | 管线用 sharp 解码 | 导入报错 |

> 第 3 条如果搞不定：在导出设置里选 **"Y-up → Z-up 标准导出"**（Blender/Blender 插件里通常写作
> *+Y up* 或 *glTF 标准坐标*）。我们这边**不做自动纠偏**是刻意的 —— 猜错了会把模型躺倒，
> 而且很难发现自己躺倒了。宁可体检拦下来，也不要静默出错。

## 三、建议达到的规格（不阻塞，但直接决定观感与体积）

| 项 | 当前基准 | 建议 |
|---|---|---|
| 三角形数 | 约 **150 万面** | **不要低于它**。低于 20 万面体检会警告"细节可能反而更少" |
| 贴图边长 | 4096² | 保持 4096²；管线会按档位缩到 2048/1536 与 768 |
| 贴图通道差异化 | 三张同尺寸 | 有精力的话：基础色最细、法线次之、金属粗糙可中等（后者变化是低频的） |
| 节点缩放 | 多为 1 | 归一化为 1（非 1 也能处理，但会让"轴长"含义变模糊） |
| 模型高度 | 管线统一归一到 **2.7 世界单位** | 你**不需要**手动缩放，交原始比例即可；但请保持角色正面朝 **+Z**、站立朝 **+Y** |

**贴图分辨率不是越高越好**：AI 图生 3D 的 UV 被切成约 2000 个碎岛（实测 UV 覆盖率仅 44~50.6%），
2048² 上每个碎岛只有约 1150 像素。**如果重制时能顺带改善 UV 布局（更少、更连续的岛），
画质提升会比单纯堆分辨率大得多** —— 这是性价比最高的一项。

## 四、风格与内容要求（与史料口径有关）

1. **卡通/风格化**，不是写实：史诗本身是程式化、理想化的，写实必然要编造长相细节。
2. **靠职分与道具区分人物，不靠脸**：
   先知→卷轴法杖；力士→宽肩粗臂；美男子→长披风；掌马→马具；射手→弓与箭袋；说书人→乐器/经卷。
3. **正面站立、四肢分开、白底单角色**：图生 3D 最容易在"侧影重叠、手部交叠、毛发细丝"上失败，
   这恰好是写实最容易踩的坑。**三视图（正/侧/背）比只给正视图效果差别很大**，背面最容易被忽略。
4. **不要生成场景**：先只要白底单角色，场景留给后续的虚幻引擎 / 线下部分。
5. 每尊的**提示词与设计要点**见 `tools/research/十二英雄形象研究.md` 第三章（含通用模板与否定词）。

## 五、交付流程（你只做第 1 步，其余我来跑）

```powershell
# 1) 把重制好的模型放成这个命名（slug 见下表）：
#    models2/<slug>.glb
#    例：models2/jiangger.glb

# 2) 体检：先花 10 秒确认格式合格（不满足会直接告诉你哪里不对、怎么改）
node scripts/ingest-models.mjs --check

# 3) 出两档 + 校验（预览档给首屏与离线预缓存，精细档给细看时加载）
node scripts/ingest-models.mjs

# 4) 重新构建（生成内容哈希名与离线预缓存清单）
npm run build
npm run preview
```

> **不用管画质档位**：默认细档与仓库现状一致（`QUALITY=normal`）。
> 想整体提档要显式指定，例如 `QUALITY=high node scripts/ingest-models.mjs` ——
> 这样"接入一个模型"绝不会顺手改掉另外十一尊的观感与体积。
>
> **如果出档时报找不到 sharp**：那是开发期的贴图编码库，本项目刻意不装（官网运行时不需要）。
> 脚本会自己在本机找一份；找不到时按提示临时指路即可：
> `$env:SHARP_MODULE="D:\已有路径\node_modules\sharp"`。

**建议先打样一尊**（推荐**洪古尔**：史料依据最实——名字意为"红色的"、史诗写他"头大如锅"、性格刚猛，
最容易做出辨识度），跑通全链路再批量做。

## 六、体积预算（网站侧已定，你交付原始模型即可）

管线会自动压到这两个档位，**不需要你预先压缩**：

| 档位 | 用途 | 预算 | 实测（当前批次） |
|---|---|---|---|
| 预览档 | 首屏立刻可交互 + **离线预缓存** | ≤ 750 KiB/尊 | 约 519~678 KiB |
| 精细档 | 细看时自动升级 | ≤ 6 MiB/尊，合计 ≤ 80 MiB | 约 4.8 MiB/尊 |

> 为什么不用你的原始文件直接上线：原始约 **70~84 MiB/尊**，浏览器端要下几十秒，
> 小程序更是塞不进去（云存储单文件上限 50 MB）。所以必须走管线。

---

## 七、接入后我会做什么（你交付完可以不管）

1. 逐尊跑管线出两档，并校验属性类型、模型高度、索引范围、体积预算；
2. 重新构建，更新内容哈希与离线预缓存清单；
3. 截图对比观感变化（`scripts/audit-visual.cjs`），确认没有回归；
4. 更新图鉴文案，并把"红色战甲/雄狮披风"这类**设计演绎**统一标注为「本项目文创演绎」口径；
5. 模型到位后再做**纹样标注**（方案 3）—— 那时"指着模型讲细节"才站得住。
